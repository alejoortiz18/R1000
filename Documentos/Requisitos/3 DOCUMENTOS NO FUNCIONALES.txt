INTRODUCCIÓN Este documento define los requisitos no funcionales del sistema Rickoin , los cuales establecen: cómo debe comportarse el sistema niveles de calidad restricciones técnicas condiciones de seguridad y cumplimiento 2. CLASIFICACIÓN DE REQUISITOS Los requisitos no funcionales se clasifican en: Seguridad Rendimiento Disponibilidad Escalabilidad Auditoría Cumplimiento legal Usabilidad Mantenibilidad 3. SEGURIDAD (CRÍTICO) 3.1 Autenticación login mediante email y contraseña cifrado de contraseñas (hash , salt seguro) bloqueo tras múltiples intentos fallidos 3.2 Autorización control por roles (Usuario / Administrador) restricción de acceso a funcionalidades 3.3 Doble factor de autenticación (2FA) requerido para: retiros operaciones sensibles código OTP enviado por correo expiración máxima: 15 minutos 3.4 Validación de identidad (KYC) carga de documento de identidad validación de mayoría de edad verificación de datos 3.5 Protección de datos cifrado de información sensible almacenamiento seguro de documentos cumplimiento de Ley 1581 de 2012 3.6 Prevención de fraude monitoreo de actividad sospechosa validación de comportamiento anómalo bloqueo automático 4. INTEGRIDAD FINANCIERA (CRÍTICO) 4.1 Consistencia de transacciones toda operación debe registrarse no se permiten inconsistencias de saldo 4.2 Atomicidad operaciones deben ser atómicas (todo o nada) 4.3 Validación de saldo no permitir saldo negativo validación previa a cualquier operación 4.4 Concurrencia evitar doble compra de boletas uso de transacciones en base de datos 5. AUDITORÍA Y TRAZABILIDAD 5.1 Registro de eventos El sistema debe registrar: accesos compras retiros cambios administrativos 5.2 Logs Cada evento debe contener: usuario fecha y hora acción realizada resultado 5.3 Trazabilidad completa Debe poder responder: quién hizo qué cuando por qué 5.4 Cumplimiento regulatorio El sistema debe estar preparado para auditoría por entidades como Coljuegos 6. RENDIMIENTO 6.1 Tiempo de respuesta operaciones normales: &lt; 2 segundos operaciones críticas: &lt; 5 segundos 6.2 Capacidad soportar múltiples usuarios concurrentes sin degradación significativa 7. DISPONIBILIDAD DE LA APLICACIÓN 7.1 Todo el tiempo mínimo: 99.5% 7.2 Recuperación sistema debe recuperarse ante fallos 8. ESCALABILIDAD 8.1 Escalado horizontal posibilidad de aumentar instancias 8.2 Base de datos optimización mediante índices consultas eficientes 9. USABILIDAD 9.1 Interfaz intuitiva clara responsive 9.2 Accesibilidad compatible con múltiples dispositivos 10.
